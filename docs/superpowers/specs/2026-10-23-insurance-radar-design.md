# 보험 레이더: 개인 보험 정보 사이트 설계

작성일: 2026-10-23
작업 폴더: `F:\VibeCoding\insurance-radar\`
디자인 기준: 웹은 `design/v4/2.html`("앞뒤로 넓힌 띠"), 모바일은 `design/v5/mobile.html`(같은 화면의 반응형판, 승인 대기)
논의 기록: `design/notes.md`
참고한 이전 프로젝트: vibe-radar (`F:\VibeCoding\trends-rebuild\`, 설계 문서 `docs/superpowers/specs/2026-10-22-vibe-radar-design.md`)

## 1. 왜 만드는가

사용자는 개인 보험(자동차, 실손, 생명·건강·상해 등) 정보를 한곳에서 보고 싶다. 사용자가 한 말을 정리하면 이렇다.

- "모든 정보들을 다양하게 모아서 보고 싶은데, 그것을 할 수 없었음."
- "보험 약관의 변화나 뉴스에서 새로 나오는 정보들도 알기 힘들었음."
- "지금은 이것을 만들어서 여기에서만 보고 싶음."

이 정보는 **본인과 가족의 보험을 다시 점검하고, 현재 내용을 확인하고, 새 가입을 판단하는 데** 쓴다. 그래서 소식을 읽는 데서 끝나지 않고, "우리 집 보험에 영향이 있나"를 빨리 판단할 수 있어야 한다. 특히 **언제부터 무엇이 바뀌는지**(약관 개정, 보험료 인상·인하, 제도 변경, 시행일)를 놓치지 않는 것이 핵심이다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

### 목표
1. 매일 자동으로 갱신되는 정적 사이트 하나에 개인 보험 소식을 모은다. 대상은 뉴스, 업계 동향, 핫이슈, 새 정보, 보험 내용 변경, 보험사 발표, 정부 발표다.
2. 첫 화면 맨 위에서 **"바뀌는 것"이 한눈에** 보인다. 화면은 시안 v4-2를 따른다.
3. 모바일에서도 쉽게 볼 수 있다. 화면은 시안 v5 mobile을 따른다.
4. 출처를 나중에 늘리기 쉬운 구조로 만든다. 특히 네이버 뉴스 검색 API를 설정과 수집기 하나만 추가해서 붙일 수 있어야 한다.
5. 서버 비용 없이 운영한다.

### 이번에 하지 않을 것
- 기업보험(기업성 보험, 단체보험, 기업 배상책임 등) 소식. 사용자가 필요 없다고 했다.
- 네이버 뉴스 검색 API 등 일반 언론 기사 수집. 지금은 보험 전문지만 쓰고, 나중에 붙인다(사용자 결정).
- 보험료 비교 계산, 가입 상담, 상품 추천
- 로그인, 서버에 저장하는 개인화, 알림, 댓글
- 가족의 실제 보험 정보를 사이트에 넣는 것. 사이트가 공개되기 때문이다.
- 지난 날짜 화면 보기. 데이터는 날짜별로 쌓아 두지만, 날짜를 골라 보는 화면은 이번에 만들지 않는다(내 판단: v4-2에 없는 기능이다).
- HWP 첨부 해석. PDF만 읽는다(5.4 참고).

### 실패로 보는 것 (돌아가도 실패)
- **지어낸 데이터가 사이트에 나가는 것.** 시안의 시안용 요약 문장도 포함한다. 데이터가 없으면 없다고 보여 준다.
- **틀린 시행일이 정확한 날짜처럼 보이는 것.** 원문에 정확한 날짜가 없는데 날짜를 계산해서 축에 찍으면 실패다. 보험은 금액·비율·날짜가 핵심이라 vibe-radar보다 엄격해야 한다.
- AI 요약에 원문에 없는 금액, 비율, 날짜, 원인이 들어가는 것
- 출처 하나가 실패해서 하루치 갱신 전체가 멈추는 것
- 매일 해야 하는 일 중 하나라도 사람(또는 Claude)이 손으로 해야 하는 것. 사용자 원칙: 매일 도는 일은 반드시 코드와 GitHub Actions로 자동이어야 한다.
- 유료 API 키가 있어야만 돌아가는 것
- 모바일에서 가로로 스크롤해야만 핵심을 이해할 수 있는 것

## 3. 제약

- 정적 사이트로 만든다. GitHub Actions가 매일 00:00 UTC(09:00 KST)에 수집·가공·요약·빌드하고 GitHub Pages로 배포한다. 수동 실행(`workflow_dispatch`)도 가능하게 한다.
- 이 PC에는 `gh` CLI가 없다. 공개 저장소는 사용자가 GitHub 웹에서 만들고(계정 `makieel`), Pages Source를 "GitHub Actions"로 먼저 설정한 뒤 push한다. vibe-radar 때와 같다.
- 새 저장소의 첫 push는 경로 필터가 걸린 워크플로를 자동 실행하지 않았다. 첫 실행은 Actions에서 수동으로 한다.
- git 작성자는 이 저장소에만 `leej` / 사용자 이메일로 설정한다.
- **AI는 Google Gemini API 무료 등급(OpenAI 호환 엔드포인트)만 쓴다.** GitHub Models는 2026-07-30에 종료됐다. 키는 저장소 Secret `GEMINI_API_KEY`에 둔다. 무료 한도는 프로젝트 단위로 적용되고 공식 문서에 숫자가 없다(AI Studio에서만 보인다). vibe-radar와 같은 키를 쓰면 두 사이트가 한도를 나눠 쓰므로, 별도 프로젝트의 키를 권한다.
- 키가 없거나 AI 호출이 실패해도 사이트는 정상으로 나와야 한다. 이때는 요약 없이 제목·출처·원문 링크만 보여 준다.
- 로컬 실행은 키 없이 된다. 이때는 요약을 건너뛴다.
- 로컬 환경: Node v24.21.0. Node의 타입 스트리핑으로 빌드 없이 `.ts`를 실행한다. Python 3.13이 있지만 사이트 코드에는 쓰지 않는다.
- 일부 출처는 해외 IP(GitHub Actions)에서 막힐 수 있다. 2026-10-23 확인은 모두 한국 IP에서 했다. 그래서 **구현 첫 단계에서 Actions로 출처 접속만 시험하는 워크플로를 먼저 돌린다.** 막히는 출처는 사용자에게 알리고, 그 출처만 실패로 표시한 채 나머지를 진행한다.
- 출처 사이트의 robots.txt가 막는 경로는 수집하지 않는다. 생명보험협회 공시실(`pub.insure.or.kr`)과 DB손해보험이 여기에 해당한다.
- 보험 전문지 기사 페이지에 "무단 전재·복사·배포 금지" 문구가 있다. 그래서 기사 본문을 사이트에 옮기지 않는다. 화면에는 제목, 짧은 AI 요약, 출처, 원문 링크만 보여 준다. 본문 발췌는 AI 요약의 근거로만 쓰고 저장소에 오래 두지 않는다(5.2 참고).

## 4. 사용자가 정한 것

- **대상:** 자동차보험, 개인보험(생명·건강·상해 등), 실손의료보험 등 개인 보험. 기업보험은 뺀다.
- **첫 화면:** 맨 위에 "바뀌는 것"을 둔다. 그 아래에 오늘 새로 나온 소식(정부·감독기관 발표, 보험사 발표, 뉴스)을 두고, 보험 종류별로 골라 볼 수 있게 한다. 각 소식에는 짧은 요약과 원문 링크를 붙인다.
- **시행일 규칙:** "시행일이 있으면 정확하게, 없으면 원래의 정보 그대로(예: 다음달 or 9월 등)." 원문에 정확한 날짜가 있으면 그 날짜를 쓰고, 없으면 원문 표현을 그대로 쓴다.
- **출처:** 확인을 거쳐 아래로 정했다(5.3 참고). 일반 뉴스는 "지금은 전문지만으로 시작하고, 나중에 API 형식을 추가하는 방향으로 확장성 여지를 남겨둬."
- **업계 동향:** 보험사 실적, 인사, 설계사 수수료 같은 업계 내부 소식은 따로 "업계 동향" 칸에 모은다.
- **디자인:** 웹은 시안 v4-2 "앞뒤로 넓힌 띠"로 확정했다. 모바일에서도 쉽게 볼 수 있어야 한다.
- **라이트·다크:** 토글로 전환한다. 기본은 밝은 모드다.
- **AI 요약:** Gemini 무료 API를 쓰고, vibe-radar의 근거 검증 장치를 이어받는다.

## 5. 내가 정한 것 (사용자가 바꿀 수 있음)

### 5.1 기술 구성
vibe-radar 구조를 그대로 따른다.
- 수집·가공: Node 24 + TypeScript(빌드 없이 실행). 의존성은 vibe-radar 수준으로 최소화한다(`fast-xml-parser`, `node-html-parser`, `zod`에 PDF 텍스트 추출 라이브러리 하나를 더한다).
- 화면: 프레임워크 없이 HTML, CSS, 브라우저 ES 모듈로 만든다. `web/core/`(데이터 불러오기, 라이트·다크, 이스케이프, 날짜 형식)와 `web/themes/<이름>/`(화면 마크업과 CSS)로 나눈다. 테마는 시안 v4-2를 옮긴 것 하나만 만든다.
- `src/schema.ts`(zod)가 데이터와 화면 사이의 유일한 약속이다. 빌드할 때 검증한다.
- 설정은 `config.json` 한 곳에 모은다. 출처 목록, 분류 키워드, AI 설정이 들어간다.
- 저장소 이름은 `insurance-radar`, 사이트 제목은 "보험 레이더"로 한다(시안에서 써 온 이름).

### 5.2 데이터 흐름과 저장

```
[수집] collect    출처별 수집기 → data/raw/YYYY-MM-DD.json     (KST 날짜, 같은 날 재실행 시 덮어씀)
[가공] analyze    분류, 묶기, 시행일 추출, 공시표 비교 → data/daily/YYYY-MM-DD.json
                   + 누적 변경 목록 data/changes.json 갱신
[요약] summarize  Gemini 요약 + 근거 검증 → daily 파일에 채움 (실패해도 진행)
[빌드] build      web/data/latest.json (오늘 화면 데이터) 생성, 스키마 검증
[배포] Pages      web/ 폴더 전체
```

- **누적 변경 목록(`data/changes.json`):** "바뀌는 것"은 몇 달 전에 발표되는 경우가 많다. 그래서 날짜별 파일과 별도로 변경 항목을 계속 쌓는다.
  - 정확한 날짜 항목은 시행일이 지나고 6개월이 될 때까지 둔다. 띠의 최대 범위가 ±6개월이기 때문이다.
  - 기간 표현 항목('27.1분기 중 등)은 그 기간이 끝나고 6개월이 될 때까지 둔다.
  - 기간을 특정할 수 없는 항목은 발표일부터 6개월 동안 둔다.
  - 같은 변경이 여러 번 보도되면 하나로 합치고 출처를 늘린다.
- **공시표 상태(`data/rates.json`):** 손해보험협회 자동차보험료 조정표를 매일 받아 전날과 비교한다. 새 행만 변경 항목으로 올린다.
- **본문 발췌:** 요약 근거로 쓴 기사 발췌와 PDF 텍스트는 raw 파일에 넣지 않는다. 필요하면 하루치 작업용 임시 파일로만 쓰고 커밋하지 않는다. 저장소에는 제목, 날짜, URL, 시행일 근거 문구(원문 한 문장 이내), AI 요약만 남긴다.
- **첫 실행 채우기:** 첫 실행 때는 각 출처의 목록을 6개월치(또는 출처별 최대 쪽수)까지 읽어 변경 목록을 채운다. 그래야 띠의 과거 쪽이 비지 않는다. 이후에는 목록 1~2쪽만 읽는다.
- **출처별 독립 실패:** 수집기마다 성공, 실패, 건수를 기록한다. 결과가 0건이면 실패로 본다. 실패는 화면 수집 상태에 보여 준다.

### 5.3 출처와 수집 방법

2026-10-23에 한국 IP에서 직접 요청해 확인한 결과다. 모두 UTF-8이고, 서버에서 다 만든 HTML(SSR)이라 헤드리스 브라우저가 필요 없다. 요청에는 고정 User-Agent(`Mozilla/5.0 (compatible; insurance-radar/1.0; +저장소 URL)`)를 붙인다. 손해보험협회와 금융감독원의 보안 장치가 `curl/*`, `Wget`, `python-requests` 같은 UA를 막고, 금감원은 UA에 "bot"이 들어가도 연결을 끊는다(2026-10-23 확인).

| 출처 | 수집 방법 | 비고 |
|---|---|---|
| 금융위원회 보도자료 | RSS(`fsc.go.kr/about/fsc_bbs_rss/?fid=0111`)를 먼저 시도하고, 실패하면 HTML 목록 `fsc.go.kr/no010101?srchKey=dept&srchText=보험과&cntPerPage=50`과 제목 "보험" 검색을 쓴다 | RSS는 지금 503 "점검 중"이다. 상세 페이지 본문이 HTML 텍스트라 시행일 추출에 가장 좋다 |

| 보험사 보도자료 4곳 | 한화생명 JSON API, 교보생명 RSS `news.kyobo.com/feed/`(보도자료 카테고리만), 삼성화재 JSON API(`VH.HDBS0101`), 메리츠화재 JSON API(`json.smart`) | 삼성생명, 현대해상, KB손보는 보도자료 메뉴가 없고 DB손보는 robots가 막아서 뺀다 |
| 보험 전문지 4곳 | RSS: 한국보험신문, 보험신보, 보험저널은 `cdn.<도메인>/rss/gn_rss_allArticle.xml`(본문 포함), 보험매일은 `fins.co.kr/rss/allArticle.xml`(요약만, 본문은 기사 페이지에서) | 합쳐서 하루 약 35건이다. 피드가 50건이라 하루 한 번 수집해도 빠지지 않는다 |

자세한 확인 기록과 요청 형식(주소, 파라미터, 헤더, 쪽 넘김, 응답 구조)은 `docs/recon/2026-10-23-source-recon.md`에 있다. 요청을 재현하는 스크립트는 `docs/recon/scripts/`에 있다(삼성화재 `sf.mjs`, 메리츠화재 `meritz.mjs`, 전문지 RSS `rss.mjs`, 손보협회 UA 시험 `assoc-ua-test.mjs`).

**확장 구조:** 수집기는 종류별 틀로 나눈다. `rss`, `html-list`(목록 + 상세), `json-api`, `table`(공시표). `config.json`의 출처 항목은 종류, 주소, 거르는 조건, 필요한 비밀 키 이름(`keyEnv`)을 가진다. 네이버 뉴스 검색 API는 나중에 `json-api` 틀의 출처 하나로 붙인다. 그때 필요한 것은 수집기 파일 하나, 설정 몇 줄, Secret(`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`)이고, 분석·요약·화면 코드는 바꾸지 않는다. 키가 없으면 그 출처는 "꺼짐"으로 표시하고 건너뛴다.

**지금 쓰지 않는 출처와 이유:** Google 뉴스 RSS(원문 링크를 비공식 경로로만 얻을 수 있고 금방 차단됐다. 이용 조건도 비상업으로 제한), 연합뉴스 RSS(8시간치뿐이고 비상업 조건), 정책브리핑 RSS(2026-07-01 폐지), 법령 Open API(서버 IP 등록이 필요해 Actions에서 쓸 수 없음), 보험다모아·파인(갱신이 거의 없거나 보험료 비교에 개인정보 입력이 필요함).

### 5.4 가공 규칙

**보험 종류 분류**
- 모든 항목을 `자동차 / 실손 / 생명·건강·상해 / 제도·공통` 중 하나로 분류한다. 키워드 사전은 `config.json`에 둔다.
- 업계 내부 소식(실적, 순익, 인사, 설계사·GA 영업, 판매수수료, 주가, 사회공헌, 행사, 채용·입찰)은 `업계 동향`으로 보낸다. 다만 제도 변경과 겹치면(예: 판매수수료 제도 개편 시행) 변경 항목으로도 올린다.
- 기업보험 소식(기업성 보험, 단체보험, 중소기업 사이버보험, 기업 배상책임 등)은 뺀다. 판단이 애매하면 뺀다.
- 은행·카드·증권 등 보험과 무관한 금융 소식은 뺀다. 전문지 피드에 섞여 있다(예: 은행 실적).

**같은 소식 묶기**
- 같은 사건을 다룬 항목을 출처와 상관없이 하나로 묶는다. 기준은 공식 발표 제목 일치, 제목 핵심어 겹침, 같은 날짜다. 묶음의 대표는 공식 발표(정부 → 협회 → 보험사 → 언론 순)로 한다. 화면에는 "N곳 보도"를 붙인다.

**시행일 추출 ("바뀌는 것")**
- 후보는 세 곳에서 나온다. (1) 공시표의 새 행: 시행시기 YYYYMMDD를 그대로 쓰고 정확한 날짜로 본다. (2) 금융위·금감원·협회 보도자료 본문(HTML 텍스트 또는 PDF 텍스트). (3) 전문지 기사 본문.
- (2)와 (3)은 정규식으로 후보 문장을 찾고, AI가 변경 항목인지와 시행일 문구를 판정한다. **AI가 낸 근거 문구는 원문에 글자 그대로 있어야 한다.** 없으면 버린다.
- **정확한 날짜로 보는 경우:** 근거 문구 안에 연·월·일이 모두 있을 때뿐이다. 예: `'26.10.12.`, `2027년 1월 1일`, `20260926`, `'26.9.10. 이후 사고부터`.
- **원문 표현으로 두는 경우:** 그 밖의 모든 경우다. 예: `다음 달부터`, `오는 25일부터`, `'27.1분기 중`, `연말까지`, `하반기`. 날짜를 계산하지 않는다. 화면에는 원문 표현과 발표일(또는 기사 날짜)을 함께 보여 준다.
- **연도 없는 월·일(`7.1일부터`, `11월 1일부터`)**: 사용자 확인이 필요하다(8장 질문 2). 확인 전까지는 원문 표현으로 둔다.
- **기간 막대(v4-2):** 원문이 기간을 명시할 때만 띠에 점선 막대로 그린다. `'YY.N월` → 그 달, `'YY.N분기` → 그 분기, `'YY 상반기/하반기` → 그 반기, `연말까지` → 오늘부터 그해 12월 31일, `YYYY년 중` → 그해. 연도가 없는 표현(`9월`, `하반기`)은 막대를 그리지 않는다. 띠 아래에 "점선 막대 = 원문이 말한 기간. 정확한 날짜가 아님"을 적는다.
- 지난 일인데 날짜가 미확정인 항목에는 "(지난 일)"을 붙인다. 이 판단은 원문 표현과 기사 날짜로 할 수 있을 때만 한다. 할 수 없으면 예정 쪽 미확정 묶음에 그대로 둔다.
- **무엇을 변경 항목으로 올리는지:** 사용자 확인이 필요하다(8장 질문 1). 확인 전 기본값은 이렇다. 제도·약관·보험료 변경 중 시행 시점이 있는 것(업계 전체 또는 특정 보험사의 보험료 조정)은 올린다. 입법·규정변경예고는 "예고 · 확정 아님" 딱지를 붙여 올린다. 보험사 한 곳의 상품 출시·개정은 변경 항목이 아니라 소식으로 보낸다. 국감 지적, "추진", "검토" 수준은 올리지 않는다.

**AI를 쓸 수 없을 때의 "바뀌는 것"** (내 판단, 검토에서 나온 질문)
- 키가 없거나, AI 호출이 실패하거나, 그날 한도를 다 쓰면 AI 판정 없이 다음만 올린다. (1) 공시표의 새 행. (2) 금융위·금감원·협회 공식 발표 본문에서 정규식으로 찾은 문장 중, 연·월·일이 모두 있고 "시행", "적용", "부터", "운영" 중 하나가 같은 문장에 있는 것. 근거 문구는 원문을 그대로 잘라 쓰므로 지어낼 여지가 없다. 전문지 기사는 AI 판정 없이는 올리지 않는다.
- 변경 판정에는 "검증이 실패하면 그날 결과를 모두 버린다" 규칙을 쓰지 않는다. 대신 근거 문구가 원문에 글자 그대로 있는지를 코드로 확인한다. 이 확인을 통과하지 못한 판정은 버린다.
- AI 판정 대기 목록을 둔다. 하루 AI 호출 상한(요약과 판정을 합쳐 설정값)을 넘는 후보는 다음 날로 넘긴다. 첫 실행 채우기에서 나온 6개월치 후보는 공식 출처부터 며칠에 걸쳐 처리한다. 그동안 띠에는 위의 AI 없는 경로로 찾은 항목이 먼저 보인다.
- 그래서 analyze는 키 없이도 돈다. AI 판정은 summarize 단계에서 요약과 함께 처리하고, 결과를 변경 목록에 반영한다.

**아래쪽 칸의 범위** (내 판단, 검토에서 나온 질문)
- 처음 본 날을 기록하는 상태 파일(`data/seen.json`, 항목 URL·ID별 처음 수집한 KST 날짜)을 둔다.
- "오늘 소식"은 최근 3일 동안 처음 본 소식을 날짜별(오늘·어제·그제)로 묶어 보여 준다. 보험사 보도자료도 여기에 "보험사 발표" 딱지를 붙여 넣는다.
- "공식 발표"는 금융위·금감원·협회·보험연구원 발표 중 업계 동향이 아닌 것을 최근 30일치 보여 준다.
- "업계 동향"은 최근 14일치를 보여 준다.
- build는 최근 30일 daily 파일을 모아 `latest.json`을 만든다.

**첨부 PDF**
- 금감원·협회 보도자료는 본문이 첨부에만 있다. PDF 첨부를 받아 텍스트를 뽑아 시행일 추출과 요약 근거에 쓴다. HWP·HWPX는 읽지 않고 링크만 둔다. 이 경우 시행일을 찾지 못하면 "시행일 미상, 첨부 확인"으로 두고 변경 항목으로는 올리지 않는다.
- 하루 받는 첨부 수와 크기에 상한을 둔다(만드는 사람이 정한다).

**AI 요약과 근거 검증** (vibe-radar `src/summarize/`를 옮기고 보험에 맞게 강화)
- 요약 대상: 그날 새 묶음 중 우선순위가 높은 것부터 하루 상한(처음에는 30개, 설정값)까지. 순서는 공식 발표 → 변경 항목이 있는 묶음 → 여러 곳에서 보도된 묶음 → 나머지다.
- 요약은 해요체 1~3문장이다. 원문 발췌가 없으면 제목을 풀어 쓴 1문장만 허용한다.
- 규칙 검사: 요약에 나온 숫자(금액, 비율, 날짜, 건수)는 모두 원문에 있어야 한다. 발췌 없이 2문장 이상이면 버린다.
- AI 2차 검증: 원문에 없는 원인, 수치, 발언, 전망이 있으면 버린다. 검증 호출이 실패하면 그날 요약을 모두 버린다.
- 실패하거나 버려진 항목은 요약 없이 제목, 출처, 원문 링크만 보여 준다.
- 모델 설정은 vibe-radar처럼 `config.json`의 `ai`(baseUrl, keyEnv, models 후보 목록, timeoutMs)에 둔다. 느린 모델은 시간 초과가 나므로 flash-lite부터 시도한다.

### 5.5 화면

**공통**
- 화면 구성은 시안 v4-2를 따른다. 위에서부터 머리(사이트 이름, 갱신 시각, 요약 숫자), ① 한눈에 보기 띠(±1·±3·±6개월, 기본 ±3, 오늘 선, 정확한 날짜 점, 기간 막대, 미확정 묶음, 보험료 조정 겹쳐 보기 토글), 띠 아래 고정 안내 줄, ② 보험 종류별 레인 표("최근 시행 | 오늘 | 예정"), 보험 종류 필터, 오늘 소식, 공식 발표, 업계 동향, 자동차보험료 조정, 수집 상태, 고지 문구 순서다.
- 모바일(좁은 화면) 구성은 시안 v5 mobile(`design/v5/mobile.html`)을 따른다. 이 시안은 설계 문서와 함께 사용자 승인을 받고, 승인 뒤에 구현을 시작한다. 시안은 데스크톱에서 v4-2와 같고 좁은 화면(767px 이하)만 다른 하나의 반응형 파일이다. 모바일에서는 띠를 화면 폭에 맞춘 압축형으로 바꾸고 기본 범위를 ±1개월로 한다. ±3·±6개월에서는 가까운 점을 "N건 묶음"으로 합친다. 띠 아래에는 시행일이 확정된 목록과 미확정 원문 표현 칩을 두고, 상세는 아래에서 올라오는 시트로 보여 준다. 레인 표는 종류별로 접고 펴는 묶음이 되고, 하단 고정 탭으로 각 섹션에 바로 간다.
- 시안의 데이터 블록과 시안용 요약 문장은 실제 사이트에 넣지 않는다. 화면은 `web/data/latest.json`만 읽는다.
- 데이터가 비면 빈 상태 문구를 보여 준다(예: "날짜가 확정된 예정 항목 없음", "오늘 새 소식 없음"). 가짜 항목으로 채우지 않는다.
- 모든 항목은 원문 링크로 연결한다(`target="_blank" rel="noopener"`).
- 고지 문구: "이 사이트는 공개된 보도자료와 기사를 자동으로 모아 보여 주는 정보 제공용이며, 보험 가입이나 해지를 권유하지 않습니다. 요약은 AI가 만들었으므로 정확한 내용은 반드시 원문과 약관에서 확인하세요." (시안 문구 그대로)
- 수집 상태: 출처별 성공·실패·건수와, 대체 경로를 쓴 경우(예: 금융위 RSS 점검 중이라 목록 페이지로 수집)를 보여 준다.

**라이트·다크** (내 판단으로 세부를 정함)
- 처음 방문하면 밝은 모드다(사용자 결정). 기기 설정은 따르지 않는다.
- 토글로 고른 값은 브라우저에 저장해 다음 방문에도 유지한다. 저장이 막힌 환경이면 밝은 모드로 연다.
- 페이지가 그려지기 전에 모드를 정해서 화면이 번쩍이지 않게 한다.
- 두 모드 모두 본문 글자는 배경 대비 4.5:1 이상이다.
- `prefers-reduced-motion`이 켜져 있으면 움직임을 끈다.

## 6. 만드는 사람에게 맡기는 것

- 파일과 모듈의 세부 구조, 테스트 방식. 수집기마다 저장한 실제 응답(fixture)으로 테스트한다.
- 분류 키워드 사전, 업계 동향·기업보험 판별 단어 목록의 세부 항목
- 묶기 알고리즘의 세부 방식
- 시행일 후보를 찾는 정규식 목록. 단, 5.4의 정확한 날짜 기준은 지킨다.
- PDF 텍스트 추출 라이브러리 선택, 첨부 수·크기 상한
- Gemini 모델 후보 순서와 하루 요약 상한의 조정
- 출처별 목록 쪽수와 첫 실행 채우기 범위의 세부
- 화면 코드를 시안에서 옮기는 방식. 단, 결과 화면은 시안과 같아야 한다.

## 7. 완료 기준

- 로컬에서 키 없이 `npm run collect && npm run analyze && npm run build`를 실행하면 실제 오늘 데이터로 v4-2 화면이 뜬다. AI 요약은 없다.
- Actions 출처 접속 시험 결과를 사용자에게 보고했다. 막힌 출처가 있으면 사용자와 처리 방법을 정했다.
- 출처를 하나 일부러 실패시켜도 나머지로 페이지가 만들어지고, 실패한 출처가 화면에 표시된다.
- 페이지에 지어낸 데이터가 없다. 정확한 날짜로 찍힌 모든 항목은 근거 문구에 연·월·일이 있거나 공시표 값이다(테스트로 확인).
- 요약 규칙 검사가 원문에 없는 숫자를 가진 요약을 버린다(테스트로 확인).
- 데스크톱(1280px)과 모바일(375·390px)에서, 라이트와 다크 두 모드 모두 깨지지 않는다. 모바일에서 페이지 전체가 가로로 스크롤되지 않는다.
- 토글을 누르면 모드가 바뀌고, 새로고침해도 유지된다. 첫 방문은 밝은 모드다.
- 네이버 API 수집기 자리(꺼진 상태의 설정 항목)가 있고, 키가 없을 때 "꺼짐"으로 표시된다.
- GitHub Actions 워크플로가 준비돼 있다. 사용자가 새 저장소를 만들고 Secret을 넣은 뒤 첫 실행을 수동으로 하면, 이후 매일 자동으로 수집·배포된다.

## 8. 사용자에게 확인할 것

1. **"바뀌는 것"에 무엇까지 넣을지.** 전문지 기사는 하루 약 35건이고 상품 출시 기사가 아주 많아서, 다 넣으면 띠가 금방 넘친다. 5.4의 기본값(제도·약관·보험료 변경만, 예고는 딱지를 붙여 넣음, 상품 출시는 소식으로, 국감·검토는 제외)으로 갈지 정해야 한다.
2. **연도 없는 월·일 표현을 정확한 날짜로 볼지.** 금융위 보도자료에 "7.1일부터 시행"처럼 연도가 빠진 날짜가 자주 나온다. 발표일 기준으로 연도를 붙이면 정확한 날짜로 띠에 찍을 수 있지만, 계산이 들어간다. 지금은 원문 표현으로 두는 쪽으로 적었다.
